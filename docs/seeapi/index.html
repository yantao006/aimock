SeeAPI Image Generation

aimock mocks SeeAPI's async image-generation protocol under the /seeapi prefix — submit a generation with an Idempotency-Key header under POST /seeapi/v1/generations, then poll it through queued → processing → succeeded | failed under GET /seeapi/v1/generations/{id}.

Endpoints

Method Path Response
POST /seeapi/v1/generations HTTP 202 { generation: { id, status: "queued", consumed_credits? } }; requires Idempotency-Key header (resubmitting returns the same generation); rejects unknown fields in input with HTTP 400 by default
GET /seeapi/v1/generations/{id} HTTP 200 { generation: { id, status, result?: { assets: [{ url }] }, error_message? } }
GET /seeapi/v1/models Static configurable list of SeeAPI models and supported endpoints

Consistent with the live SeeAPI API, there is no list endpoint: GET /seeapi/v1/generations returns HTTP 404.

Fixture Authoring

Register fixtures programmatically with mock.onSeeapiImage() or in JSON fixture files with endpoint: "seeapi". Match on model, prompt substring/regex, and optionally hasInputImages or inputImageCount.

seeapi.test.ts ts
mock.onSeeapiImage("nano-banana-2-1", {
  urls: ["https://assets.seeapi.com/generated/cat.png"],
  consumedCredits: 10,
});

// Match image-to-image requests carrying reference input_images:
mock.onSeeapiImage(
  "nano-banana-2-1",
  { urls: ["https://assets.seeapi.com/generated/edit.png"] },
  { prompt: /style/, hasInputImages: true },
);

// Failed generation:
mock.onSeeapiImage(
  "nano-banana-2-1",
  { error: "content policy violation", status: "failed" },
  { prompt: "blocked" },
);

Strict Input Field Validation

By default, SeeAPI rejects unknown keys inside body.input with HTTP 400 and a message like invalid input: unknown input field app_key. The default allowed input fields for image models are prompt, input_images, aspect_ratio, resolution, and output_format. Customize or disable this check via seeapi.allowedInputFieldsByModel, seeapi.defaultAllowedInputFields, or seeapi.strictInputFields: false.

Polling Realism & Chaos

Configure poll progression via seeapi: { pollsBeforeInProgress, pollsBeforeCompleted } at the server level or per fixture. Chaos injection applies to all SeeAPI routes, and every request is journaled under service: "seeapi".
